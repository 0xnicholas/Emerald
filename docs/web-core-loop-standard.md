# Web 核心循环标尺

> **定位**：ADR-0003「核心循环完整性」评价标准的可操作化。v0.7.0 起，`apps/web` 的发布以此单为门。
>
> **形态**：黑盒旅程验收单——在浏览器中对单机 compose 实例人工走查；条款与代码形状解耦，UI 重构不改变标尺。自动化 E2E 可日后加固，不作当前门。
>
> **姊妹文档**：现状事实（白盒审计，file:line）见 `docs/verification/web-core-loop-audit-2026-08-15.md`（分支 `research/web-core-loop-audit`，issue #48）；差距判定与补全优先级由补全计划维护（issue #50）。

## 验收环境与步骤

1. 单机 `docker compose up -d`（`docker-compose.yml`），仅 `:80` 对外可达。
2. 按文档取得 API key（H3 所指的文档化主机命令）。
3. 桌面浏览器（≥1280px）访问 `http://localhost`，以 key + Entity ID 登录。
4. 逐条走查下列条款；全绿 = 过门。

## 摄入环（Ingest）

| # | 条款 |
|---|---|
| I1 | 快速笔记保存后出现在「最近保存」 |
| I2 | 弹窗 Note 保存后可被搜索命中 |
| I3 | 弹窗 Link 保存后内容可被搜索命中 |
| I4 | 弹窗 File 上传后内容可被搜索命中 |
| I5 | 保存失败有诚实反馈；不存在假「已保存」 |

原则：UI 暴露的每个摄入入口必须真实落库且可被搜索命中；保存反馈诚实。

## 搜索环（Search）

| # | 条款 |
|---|---|
| S1 | 三态真实：memory 态命中记忆；rag 态命中已摄入文档内容（依赖 I4）；hybrid 态两类皆回 |
| S2 | Spaces 过滤可用：指定空间内搜索只见该空间记忆；不选则默认全池 |
| S3 | 摄入→可搜往返：新内容在管线完成后可被语义查询命中（与 P2 同源验收） |

不含：type/tag 客户端过滤、@提及、命令面板搜索——非核心循环，其现状由差距判定另行记录。

## 画像环（Profile）

| # | 条款 |
|---|---|
| P1 | 画像可见：静态事实 + 记忆统计 |
| P2 | 新鲜度：新摄入的静态事实在管线完成后反映到画像（无需重登/清缓存） |
| P3 | 画像是默认上下文：身份/偏好类提问（如「我是谁？」「我用什么语言写作？」）在搜索零命中时也能基于画像回答 |

P3 是引擎原则「画像先于搜索注入」（AGENTS.md 原则 5）在 web 产品层的落地。

## 对话环（Chat）

| # | 条款 |
|---|---|
| C1 | 提问后回答引用了检索到的记忆内容（非固定模板） |
| C2 | 流式输出可见（打字机或分段呈现） |
| C3 | 无 LLM key 时对话仍可用，且显式标识降级态 |
| C4 | 模型选择器真实生效，或从 UI 移除 |

对话环完成 = 真 LLM 回答 + 无 key 显式降级；未被调用的代理路径须盘活或删除。

## 横切验收（Cross-cutting）

| # | 条款 |
|---|---|
| H1 | 单机 `docker compose up -d` 后，仅 `:80` 对外即可完整走完四环验收单——客户端 API 流量全部经服务源，无硬编码主机 |
| H2 | 前端服务为生产构建（无 dev overlay、无热重载、冷启动合理） |
| H3 | 登录所需 API key 可通过文档化主机命令获得（key 自助创建 UX 延后，不在本门） |

## 移动端

零条款、零阻断力。全部条款在桌面浏览器（≥1280px）执行。对 ADR-0003 原文「移动端可用」的偏离已在 ADR-0003 修订段记录：移动端可用延后，标尺仅覆盖桌面（v0.7.0 起）。
