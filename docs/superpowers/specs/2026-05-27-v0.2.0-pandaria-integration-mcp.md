## 1. Goals & Non-Goals

### 1.1 Goals

1. **Pandaria 集成闭环** — Pandaria 通过 `MemoryStore` trait 的 HTTP adapter 调用 Emerald REST API，实现 turn 级记忆写入和上下文检索
2. **MCP Server** — 实现 Model Context Protocol 服务，任何 MCP 客户端（Claude Desktop、Cursor、Cline、Pandaria TUI 未来插件）可直接消费 Emerald
3. **通用接口稳定性** — `entity_id`、`metadata`、搜索返回结构等核心接口保持开放与通用，为未来其他 agent 系统集成预留空间
4. **连接器端到端验证** — GitHub + Google Drive OAuth 完整走通，文件自动同步后可搜索

### 1.2 Non-Goals

- **K8s 部署模板** — 仍使用 Docker Compose
- **记忆图谱可视化前端** — 仍无 Web UI
- **Chrome 插件 / Raycast** — consumer 产品形态，defer
- **高级查询改写（LLM 驱动）** — 仍是规则 stub
- **Cross-encoder 重排序** — 仍是关键词 boost stub
- **音频/视频提取生产化** — 仍是基本实现
- **Vercel AI SDK 中间件** — 非 Pandaria 生态，不做
- **LangChain 集成** — 非 Pandaria 生态，不做
- **TypeScript SDK 完整实现** — Pandaria 全栈 Rust，当前无 Node.js 消费方；骨架可预留，不发布 npm

## 3. Design Principles

### 3.1 独立基础设施，通用接口

Emerald 是独立记忆基础设施，不是 Pandaria 的专属组件。所有功能通过通用 REST API 暴露，不硬编码任何 Pandaria 特定逻辑。

**红线**：Emerald 代码库中不得出现 `pandaria_` 前缀、Pandaria 特定字段解析、或 Pandaria 特有行为分支。

### 3.2 集成在消费方实现

Pandaria 与 Emerald 的连接通过 Pandaria 侧的 `MemoryStore` HTTP adapter 实现，而非在 Emerald 侧为 Pandaria 定制接口。

```
Pandaria (Rust)                          Emerald (Python)
    │                                        │
    ├── EmeraldMemoryStore (HTTP adapter) ──►│
    │    (Rust, 在 Pandaria 侧)               │
    │                                        │
    │    POST /v1/memories                   │
    │    POST /v1/search                     │
    │    GET  /v1/profiles/{id}              │
    │                                        │
    │◄── 通用 JSON ──────────────────────────│
```

### 3.3 协议层解耦

MCP Server 作为行业标准协议层，Emerald 只实现协议，不关心调用方身份。

### 3.4 `entity_id` 作为开放命名空间

`entity_id` 是任意字符串标识符，不预设格式。Pandaria 可用 `tenant_id:session_id`，其他系统可用 `user_123`、`org:project:thread` 等任意格式。Emerald 不做格式校验或语义解析。

## 4. Pandaria Integration

### 4.1 Pandaria 侧：EmeraldMemoryStore

Pandaria 的 `agent-core` crate 已定义 `MemoryStore` trait：

```rust
#[async_trait]
pub trait MemoryStore: Send + Sync {
    async fn remember(&self, ctx: &MemoryContext, content: &str, metadata: &serde_json::Value) -> Result<(), MemoryError>;
    async fn recall(&self, ctx: &MemoryContext, query: &str) -> Result<Vec<String>, MemoryError>;
    async fn forget_session(&self, ctx: &MemoryContext) -> Result<(), MemoryError>;
}
```

**v0.2.0 在 Pandaria 侧新增 `EmeraldMemoryStore`**：

```rust
pub struct EmeraldMemoryStore {
    client: reqwest::Client,
    base_url: String,
    api_key: String,
}

#[async_trait]
impl MemoryStore for EmeraldMemoryStore {
    async fn remember(&self, ctx: &MemoryContext, content: &str, metadata: &Value) -> Result<(), MemoryError> {
        // POST /v1/memories
        // entity_id = ctx.tenant_id (Option A: cross-session recall)
        // session_id 写入 metadata 用于审计
        // metadata 透传
    }

    async fn recall(&self, ctx: &MemoryContext, query: &str) -> Result<Vec<String>, MemoryError> {
        // POST /v1/search
        // search_mode = "hybrid"
        // 返回 results[].content 列表
    }

    async fn forget_session(&self, _ctx: &MemoryContext) -> Result<(), MemoryError> {
        // v0.2.0: no-op. Emerald auto-forgetting handles time-based expiration,
        // but does NOT react to Pandaria session deletion.
        // Future: call Emerald's explicit forget API when available.
        Ok(())
    }
}
```

### 4.2 Emerald 侧：接口保障

Emerald 需确保以下接口行为对 Pandaria 完全可用，且对未来其他系统保持一致：

| 接口 | 要求 |
|---|---|
| `POST /v1/memories` | `entity_id` 支持任意字符串；`metadata` 自由写入；`content_type` 支持 `"conversation"` |
| `POST /v1/search` | 返回结构稳定（`id`、`content`、`score`、`source`、`memory_type`、`is_latest` 保证存在）；支持按 `entity_id` 精确过滤 |
| `GET /v1/profiles/{id}` | 响应格式冻结；`static` / `dynamic` 数组保证存在 |
| `metadata` 透传 | 写入时的 `metadata` 在搜索时可选择返回（v0.2.0 至少保证写入不丢失） |

### 4.3 Hook 联动机制

Pandaria 的 `MemoryHookDispatcher` 在三个 hook 点调用 `MemoryStore`：

| Hook 点 | Emerald 行为 | 超时 |
|---|---|---|
| `on_turn_end` | `remember()` 发送 Markdown transcript + metadata | 5s，失败静默丢弃 |
| `on_context` | `recall()` 检索相关记忆，注入 `[Memory]` 用户消息 | 3s，失败不注入 |
| `on_compact_end` | `remember()` 发送 compaction summary（`importance=8`） | 5s，失败静默丢弃 |

### 4.4 Entity 映射策略与已知限制

Pandaria 的 `tenant_id` 直接作为 Emerald 的 `entity_id`，`session_id` 放入 `metadata`。

**优点：**
- 同一会话内的 turn 自动关联
- 无需额外的用户/租户映射层，实现简单

**已知限制（跨 session 隔离）：**
由于 `entity_id = tenant_id:session_id`，不同 session 的记忆在 Emerald 中是完全隔离的。这意味着：
- Session 1 中用户说"我喜欢 TypeScript"
- Session 2 中同一用户问"我该学什么语言？"
- `recall()` 不会返回 Session 1 的偏好，因为 entity_id 不同

**缓解方案（当前推荐选项 A）：**
- **选项 A**：Pandaria 侧使用 `tenant_id`（不含 `session_id`）作为 `entity_id`，将 `session_id` 放入 `metadata` 中用于审计。这符合 Emerald"用户画像属于用户，不属于单次会话"的设计意图。v0.2.0 采用此方案。
- **选项 B**：Pandaria 侧 `recall()` 时同时查询 `tenant_id` 和 `tenant_id:session_id` 两个 entity（需 Emerald 支持多 entity 查询）— v0.2.0 不做。
- **选项 C**：保持当前设计，在文档中声明"v0.2.0 按 session 隔离，跨 session 聚合为后续版本"。

> **v0.2.0 决策：** 采用选项 A。`entity_id = tenant_id`，`metadata["session_id"] = session_id`。

## 5. MCP Server

### 5.1 协议概述

Model Context Protocol (MCP) 是 Anthropic 推出的开放协议，允许 AI 助手通过标准化接口调用外部工具。Emerald MCP Server 暴露以下能力：

| 工具名 | 功能 | 对应 API | 状态 |
|---|---|---|---|
| `emerald_add` | 添加记忆 | `POST /v1/memories` | v0.2.0 实现 |
| `emerald_search` | 搜索记忆 | `POST /v1/search` | v0.2.0 实现 |
| `emerald_profile` | 获取用户画像 | `GET /v1/profiles/{id}` | v0.2.0 实现 |
| `emerald_upload` | 上传文件 | `POST /v1/upload` | 暂缓（Pandaria 侧无直接需求）|

### 5.2 实现

```python
# emerald/mcp/server.py
from mcp.server.fastmcp import FastMCP
from emerald.sdk.client import EmeraldClient

mcp = FastMCP("emerald")

_client: EmeraldClient | None = None

def _get_client() -> EmeraldClient:
    global _client
    if _client is None:
        api_key = os.environ["EMERALD_API_KEY"]
        base_url = os.environ.get("EMERALD_BASE_URL", "http://localhost:8000")
        _client = EmeraldClient(api_key=api_key, base_url=base_url)
    return _client

@mcp.tool()
async def emerald_add(content: str, entity_id: str) -> dict:
    """Add a memory to Emerald."""
    ...

@mcp.tool()
async def emerald_search(q: str, entity_id: str, search_mode: str = "hybrid") -> dict:
    """Search memories and documents in Emerald."""
    ...

@mcp.tool()
async def emerald_profile(entity_id: str) -> dict:
    """Get user profile from Emerald."""
    ...
```

## 7. Interface Design Intentions (Experimental in v0.2.0)

> ⚠️ **以下接口在 v0.2.0 为实验性状态。** 经过至少一个完整集成周期验证后，再在后续版本中提升为稳定接口。

Emerald v0.2.0 为未来其他 agent 系统预留以下设计意图：

| 接口维度 | v0.2.0 实验性状态 | 验证后稳定方向 |
|---|---|---|
| `entity_id` | 任意字符串，无格式校验 | 验证前缀查询、多层级聚合的可行性 |
| `metadata` | 自由 JSON，写入不丢失；搜索时**不返回** | 验证按 metadata 字段过滤搜索的实用性 |
| `content_type` | text/conversation/url/pdf/image/audio/video/code/markdown | 按需新增 |
| `search_mode` | hybrid/memory/rag | 未来可增加 weighted 模式 |
| `memory_type` | fact/preference/episode（自动检测） | 不开放手动标记 |
| Profile 响应 | static + dynamic + memory_count | 验证 computed_at / version 语义的必要性 |

**TypeScript SDK 骨架**（`packages/sdk-ts/`）保留目录结构，v0.2.0 内不实现 HTTP 调用逻辑，不发布 npm 包。
