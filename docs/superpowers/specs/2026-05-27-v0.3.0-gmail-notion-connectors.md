# Emerald v0.3.0 — Gmail + Notion Connectors Design Spec

> **Prerequisite:** v0.2.0 tagged and pushed.
> **Goal:** Implement Gmail and Notion connectors matching existing GitHub and Google Drive pattern. OAuth → sync → pipeline ingestion.

---

## 1. Design Context

### 1.1 Why These Two

Emerald 的唯一消费者是 Pandaria。Gmail 和 Notion 是开发者日常使用的两个核心信息源：

- **Gmail** — 通信记忆：邮件中的承诺、决定、时间线。映射为 Emerald 的 episodic 记忆。
- **Notion** — 结构化知识库：项目文档、需求条目、会议记录。映射为 RAG 文档。

### 1.2 Non-Goals for v0.3.0

- Gmail Pub/Sub push webhook（GCP 配置复杂，延后到 v0.3.1）
- Notion webhooks（仍处于 beta，延后）
- 附件提取（Gmail 附件、Notion 图片/文件 block）
- 实时邮件监听
- Google OAuth token 自动刷新（延后到 v0.3.1，届时 Gmail + Drive 统一处理）
- Google OAuth 基类抽象（不重构已有 Drive 连接器）

### 1.3 Reference: Supermemory

Supermemory 已支持 Gmail + Notion。其模式为标准 OAuth → import 流程，不特殊处理。Emerald 采用相同方式。

## 2. Gmail Connector

### 2.1 OAuth Flow

与 Google Drive 共享同一个 Google Cloud 项目，使用独立的 OAuth scope：

```
scope: https://www.googleapis.com/auth/gmail.readonly
```

OAuth 流程：
1. `get_auth_url()` → 返回 Google OAuth 授权 URL（与 Drive 相同端点，不同 scope）
2. `handle_callback()` → 用 authorization code 换取 access_token + refresh_token
3. 凭证加密存储到 `connectors` 表

用户需要分别授权 Drive 和 Gmail（独立的两条 connector 记录，都关联同一个 entity_id）。

### 2.2 API Endpoints

| Gmail API | 用途 |
|---|---|
| `GET /gmail/v1/users/me/messages` | 列出邮件 ID（支持 `q=` 过滤） |
| `GET /gmail/v1/users/me/messages/{id}` | 获取邮件元数据（headers、threadId、labelIds） |
| `GET /gmail/v1/users/me/messages/{id}?format=full` | 获取邮件正文（包含 body.data） |
| `GET /gmail/v1/users/me/history` | 增量变更（startHistoryId） |

### 2.3 Data Mapping

每封邮件提取为一条 Emerald 记忆：

| 邮件字段 | Emerald 映射 |
|---|---|
| `messageId` | `document_id`（去重依据，格式 `gmail:{messageId}`） |
| `threadId` | `metadata.thread_id` |
| `From` / `To` / `Cc` | `metadata.participants` |
| `Subject` | `metadata.subject` |
| `Date`（邮件头） | `valid_from` |
| Body（提取为纯文本） | `content` |
| `labelIds` | `metadata.labels` |

### 2.4 Body Extraction

邮件的 `payload` 可能是以下 MIME 类型之一，处理优先级如下：

1. **`text/plain`** → 直接使用
2. **`text/html`** → 用正则提取纯文本：
   ```
   text = re.sub(r'<br\s*/?>', '\n', html)      # 保留换行
   text = re.sub(r'<[^>]+>', '', text)           # 去除所有 HTML 标签
   text = html.unescape(text)                     # 解码 HTML 实体 (&amp; → &)
   text = re.sub(r'\n{3,}', '\n\n', text)         # 压缩多余空行
   ```
3. **`multipart/alternative`** → 优先取 `text/plain` part，否则取 `text/html` part 再按上述流程处理
4. **`multipart/mixed`**（含附件）→ 仅提取 `text/plain` 或 `text/html` part，附件跳过
5. **base64url 编码的 body** → 先 `base64.urlsafe_b64decode(data)` 解码，再按对应 MIME 类型处理
6. **空正文**（日历邀请、已读回执等无 body 数据的邮件）→ **跳过**（不报错，不提交 pipeline，计入 `files_skipped`）

提取后的纯文本以 `content_type="text"` 提交 Emerald pipeline。

### 2.5 Sync Strategy

```
sync(mode=FULL):
  pageToken 分页遍历 messages.list(q="newer_than:30d")
  → 每个 message 检查 document_id="gmail:{messageId}" 是否已存在
  → 不存在则 GET message?format=full → 提取 body → 提交 pipeline
  → 存在则计入 files_skipped

sync(mode=INCREMENTAL):
  从 Connector.sync_metadata 读取 lastHistoryId
  → history.list(startHistoryId=lastHistoryId)
  → 筛选 historyType == "messageAdded" 事件
  → 只同步新增邮件（去重逻辑同上）
  → 更新 sync_metadata.lastHistoryId
```

#### 2.5.1 `historyId` 持久化

增量同步需要跨次调用记住上次的 `historyId`。

**存储方案：** 在 `Connector` ORM 模型新增 `sync_metadata` 列（JSONB, nullable），用于存储连接器专用的同步状态：

```json
{"lastHistoryId": "12345"}
```

- 首次全量同步开始时，从 profile（`GET /gmail/v1/users/me/profile`）获取当前 `historyId` 写入
- 每次增量同步完成后更新
- 该列为通用设计，未来 Notion 等连接器也可复用（存 `last_synced_at`、`cursor` 等）

**需要新增 Alembic migration** 添加此列（默认 `NULL`）。

### 2.6 `encrypt()` / `decrypt()` 类方法

遵循 GitHub / Google Drive 的凭据持久化模式：

```python
def encrypt(self) -> bytes | None:
    if self.credentials:
        return encrypt_credentials(self.credentials)
    return None

@classmethod
def decrypt(cls, encrypted: bytes, entity_id: str) -> "GmailConnector":
    connector = cls(entity_id=entity_id)
    connector.credentials = decrypt_credentials(encrypted)
    return connector
```

### 2.7 Webhook（延后到 v0.3.1）

Gmail push notification 需要：
1. 创建 GCP Pub/Sub topic + subscription
2. `users.watch()` 注册（每 7 天续期）
3. Pub/Sub push → Emerald webhook 端点

v0.3.0 不实现。定时同步（Celery Beat 每 4 小时）作为替代。`handle_webhook()` 返回 `False`（no-op）。

### 2.8 Config

无需新增。复用已有 `google_client_id` / `google_client_secret`。

### 2.9 文件清单

| 文件 | 操作 | 说明 |
|---|---|---|
| `emerald/connectors/gmail.py` | 重写 | 完整实现替换 stub（~350 行） |
| `emerald/connectors/registry.py` | 修改 | 注册 `gmail` |
| `emerald/models/connector.py` | 修改 | 新增 `sync_metadata` JSONB 列 |
| `migrations/versions/` | 新建 migration | `sync_metadata` 列添加 |
| `emerald/api/routes/connectors.py` | 无需修改 | 已有 `valid_providers` 含 `gmail` |
| `tests/connectors/test_gmail.py` | 新建 | Gmail connector 单元测试 |
| `tests/integration/test_gmail_e2e.py` | 新建 | E2E（需要真实 Google 凭证，CI 跳过） |

## 3. Notion Connector

### 3.1 OAuth Flow

Notion OAuth 2.0（独立于 Google）：

```
授权端点: https://api.notion.com/v1/oauth/authorize
Token 端点: https://api.notion.com/v1/oauth/token
```

OAuth 流程：
1. `get_auth_url()` → 构建 Notion OAuth 授权 URL，参数：
   - `client_id` — 来自 `notion_client_id`
   - `redirect_uri` — 必须与 Notion 集成设置中的 redirect URI **完全一致**
   - `response_type=code`
   - `state` — SHA-256 生成的 state token（与 GitHub/Drive 模式一致）
   - `owner=user` — 以用户身份授权（而非 workspace owner）
2. `handle_callback()` → `POST /v1/oauth/token`，Body:
   ```
   grant_type=authorization_code
   code={code}
   redirect_uri={redirect_uri}
   ```
   Authorization header: HTTP Basic Auth（`client_id:client_secret` base64 编码）
3. Notion access_token **不会过期**（Bot token），无 refresh_token。`ConnectorCredentials.refresh_token` 设为 `None`。

OAuth callback 响应额外包含：
- `workspace_name` — 用户选择的 workspace 名称
- `workspace_id` — workspace UUID
- `bot_id` — 集成的 bot ID

这些写入 `Connector.sync_metadata` JSONB 列，供 `status()` 展示。

### 3.2 API 请求头

所有 Notion API 请求必须携带两个头：

```
Authorization: Bearer {access_token}
Notion-Version: 2022-06-28
```

### 3.3 API Endpoints

| Notion API | 用途 |
|---|---|
| `POST /v1/search` | 搜索可访问的页面和数据库（分页，`page_size=100`） |
| `GET /v1/pages/{id}` | 获取页面属性 |
| `GET /v1/blocks/{id}/children` | 获取页面/block 的子内容（分页，`page_size=100`） |
| `POST /v1/databases/{id}/query` | 查询数据库行（分页，`page_size=100`） |

### 3.4 Data Extraction

#### 页面文本提取（递归展开 blocks）

```
get_page_content(page_id, depth=0):
  if depth > 10: return ""           # 递归深度上限
  blocks = GET /v1/blocks/{page_id}/children (分页, page_size=100)
  text = ""
  for block in blocks:
    switch block.type:
      paragraph, heading_1, heading_2, heading_3,
      bulleted_list_item, numbered_list_item, toggle,
      quote, callout
        → 提取 rich_text 中所有 text_plain → 拼接到 text

      code
        → language = block.code.language
        → code_text = 提取 rich_text → text_plain
        → 包装为 f"```{language}\n{code_text}\n```"

      child_page, child_database
        → 递归调用 get_page_content(child_id, depth+1)

      table, column_list, column, synced_block
        → 递归展开子 blocks（has_children=true 时）

      equation
        → 提取 block.equation.expression 文本（LaTeX 原文）

      image, file, video, pdf
        → 跳过（v0.3.0 不处理二进制 block）

      divider, table_of_contents, breadcrumb, link_preview,
      link_to_page, template, embed, bookmark
        → 跳过

      unsupported
        → 跳过，debug 日志记录 block.type
  return text
```

#### 数据库搜索与行提取

搜索时不加 `filter` 参数，按返回结果的 `object` 类型分流：

- `object == "page"` → 按上述逻辑展开 blocks
- `object == "database"` → 调用行提取逻辑

```
get_database_rows(database_id):
  results = POST /v1/databases/{database_id}/query (分页, page_size=100)
  rows = []
  for page in results:
    title = extract_title_from_properties(page.properties)   # 通常是 "Name" 或 "Title" 列
    cell_values = []
    for name, prop in page.properties.items():
      value = extract_property_value(prop)                    # 递归提取 rich_text/select/date 等
      if value:
        cell_values.append(f"{name}: {value}")
    rows.append(title + " | " + " | ".join(cell_values))
  return "\n".join(rows)
```

所有提取结果以 `content_type="text"` 提交 Emerald pipeline。

### 3.5 Data Mapping

每个 Notion 页面映射为一条 Emerald 记忆/文档：

| Notion 字段 | Emerald 映射 |
|---|---|
| `page.id` | `document_id`（格式 `notion:{page_id}`） |
| `page.last_edited_time` | `valid_from` / 去重依据 |
| `page.properties.title` | `metadata.title` |
| `page.url` | `metadata.url` |
| 展开后的 blocks 文本 | `content` |
| `page.parent.type` | `metadata.parent_type` |

数据库行也以 `document_id="notion:db:{db_id}:{row_id}"` 格式存储。

### 3.6 Sync Strategy

```
sync(mode=FULL):
  cursor = None
  loop:
    results = POST /v1/search (sort=last_edited_time desc, page_size=100, start_cursor=cursor)
    for item in results:
      switch item.object:
        "page" → 检查 last_edited_time vs 已存储版本 → 有变化则递归提取 → 提交 pipeline
        "database" → 提取行数据 → 提交 pipeline
    cursor = results.next_cursor
    if not cursor: break
  更新 Connector.sync_metadata.last_synced_at

sync(mode=INCREMENTAL):
  从 Connector.sync_metadata 读取 last_synced_at
  与 FULL 相同逻辑，但在 results 中：
    如果 item.last_edited_time <= last_synced_at → 停止（已按时间降序排列，之后均为旧数据）
```

Notion 不提供 history API，增量同步通过 `last_edited_time` 时间戳过滤 + 降序提前终止实现。

## 4. 共享改进

### 4.1 Registry 注册

```python
# emerald/connectors/registry.py
from emerald.connectors.gmail import GmailConnector
from emerald.connectors.notion import NotionConnector
from emerald.connectors.github import GitHubConnector
from emerald.connectors.google_drive import GoogleDriveConnector

registry.register("gmail", GmailConnector)
registry.register("notion", NotionConnector)
registry.register("github", GitHubConnector)
registry.register("google_drive", GoogleDriveConnector)
```

### 4.2 Gmail / Notion 共同模式

每个连接器必须实现以下方法以保持与已有连接器的一致性：

- `__init__(self, entity_id: str)` — 初始化
- `get_auth_url(redirect_uri)` → `tuple[str, str]` — OAuth 授权 URL + state
- `handle_callback(code, state)` → `ConnectorCredentials` — 交换 token
- `sync(mode)` → `SyncResult` — 全量/增量同步
- `handle_webhook(payload, signature)` → `bool` — Webhook 处理（v0.3.0 返回 `False`）
- `revoke()` → `None` — 撤销 OAuth
- `status()` → `ConnectorStatus` — 连接状态
- `encrypt()` → `bytes | None` — 凭据序列化（用 `emerald.connectors.auth.encrypt_credentials`）
- `decrypt(encrypted, entity_id) -> connector` — 凭据反序列化（classmethod）
- `_get_api_client()` → `httpx.AsyncClient` — 返回带认证的 HTTP 客户端

### 4.3 测试策略

| 类型 | Gmail | Notion |
|---|---|---|
| **单元测试** | Mock httpx 响应测试 OAuth、body 提取（HTML/plain/empty）、去重逻辑、historyId 存储 | Mock httpx 响应测试 OAuth、block 递归、code block 提取、数据库行提取、深度上限 |
| **集成测试** | 需要真实 Google 凭证 + 测试邮箱（CI 跳过） | 需要真实 Notion token + 测试页面（CI 跳过） |
| **边界测试** | 空邮件（跳过）、HTML only 邮件、base64 编码 body、超大正文（>1MB 截断）、未授权 401、token 过期 | 空页面、深层嵌套（>10 层截断）、超大数据库（>1000 行分页）、已撤销 token 401、429 速率限制重试 |

### 4.4 验收标准

- [ ] `POST /v1/connectors/gmail/connect` 返回有效 Google OAuth URL
- [ ] `POST /v1/connectors/notion/connect` 返回有效 Notion OAuth URL
- [ ] OAuth callback 成功后凭据加密存储到 `connectors` 表
- [ ] Gmail 全量同步摄入最近 30 天邮件 → 可通过 `search()` 查到邮件内容
- [ ] Gmail 增量同步只处理新邮件（`historyId` 递增，`sync_metadata` 更新）
- [ ] Gmail 空正文邮件被跳过（不报错）
- [ ] Gmail HTML 邮件正确提取纯文本（标签去除、实体解码）
- [ ] Notion 同步递归提取页面 blocks（含 `code` 类型 markdown fenced）
- [ ] Notion 同步搜索到 database 时自动提取行数据
- [ ] Notion block 递归 10 层后截断（不爆栈）
- [ ] 重复同步不产生重复记忆（`document_id` 去重）
- [ ] 未连接时调用 `sync()` 返回错误（不崩溃）
- [ ] `DELETE /v1/connectors/gmail` 或 `notion` 可撤销 OAuth 凭证
- [ ] Notion API 429 速率限制自动重试（指数退避，最多 3 次）
- [ ] Alembic migration `sync_metadata` 列成功执行
- [ ] 所有单元测试通过，无需外部依赖

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Gmail API 配额限制（每秒 250 单位） | 同步时加 `asyncio.sleep(0.2)` 限流 |
| Notion API 速率限制（每秒 3 请求） | 请求间加 `asyncio.sleep(0.35)` + 429 重试（指数退避，最多 3 次） |
| 大邮箱同步超时 | 限制全量同步为最近 30 天；增量同步默认 |
| Notion block 递归过深 | 设置最大递归深度 = 10 层，超过则截断并日志告警 |
| Google OAuth token 过期 | v0.3.0 不实现自动刷新（Drive 存在同样缺口）。过期后 `status()` 返回 `error` + `error_message`，引导用户重新授权。v0.3.1 统一做 refresh |
| Notion token 被用户撤销 | `status()` 调用 `POST /v1/search`（1 条）探测 → 返回 401 则标记 `error` |
| Connector.sync_metadata JSONB 膨胀 | 每个连接器只存少量字段（< 1KB），无膨胀风险 |

## 6. 不在范围内（v0.3.1+）

- Gmail Pub/Sub webhook 实时推送
- Notion webhook 实时监听
- Gmail 附件提取（PDF、图片等）
- Notion 图片和文件 block 提取
- Gmail 邮件线程上下文（同一 thread 的邮件关联）
- Notion 数据库的 filter/sort 视图处理
- Google OAuth token 自动刷新（Gmail 和 Drive 统一处理）
- 同步状态仪表板 UI
