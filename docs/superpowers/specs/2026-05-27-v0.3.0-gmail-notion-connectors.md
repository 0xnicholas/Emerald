# Emerald v0.3.0 — Gmail + Notion Connectors Design Spec

> **Prerequisite:** v0.2.0 tagged and pushed.
> **Goal:** Implement Gmail and Notion connectors matching existing GitHub and Google Drive pattern. OAuth → sync → pipeline ingestion.

---

## 1. Design Context

### 1.1 Why These Two

Emerald 的唯一消费者是 Pandaria。Gmail 和 Notion 是开发者日常使用的两个核心信息源：

- **Gmail** — 通信记忆：邮件中的承诺、决定、时间线。映射为 Emerald 的 episodic 记忆。
- **Notion** — 结构化知识库：项目文档、需求条目、会议记录。映射为 RAG 文档。

### 1.2 Non-Goals for v0.3.0

- Gmail Pub/Sub push webhook（GCP 配置复杂，延后到 v0.3.1）
- Notion webhooks（仍处于 beta，延后）
- 附件提取（Gmail 附件、Notion 图片）
- 实时邮件监听
- Google OAuth 基类抽象（不重构已有 Drive 连接器）

### 1.3 Reference: Supermemory

Supermemory 已支持 Gmail + Notion。其模式为标准 OAuth → import 流程，不特殊处理。Emerald 采用相同方式。

## 2. Gmail Connector

### 2.1 OAuth Flow

与 Google Drive 共享同一个 Google Cloud 项目，使用独立的 OAuth scope：

```
scope: https://www.googleapis.com/auth/gmail.readonly
```

OAuth 流程：
1. `get_auth_url()` → 返回 Google OAuth 授权 URL（与 Drive 相同端点，不同 scope）
2. `handle_callback()` → 用 authorization code 换取 access_token + refresh_token
3. 凭证加密存储到 `connectors` 表

用户需要分别授权 Drive 和 Gmail（独立的两条 connector 记录，都关联同一个 entity_id）。

### 2.2 API Endpoints

| Gmail API | 用途 |
|---|---|
| `GET /gmail/v1/users/me/messages` | 列出邮件 ID（支持 `q=` 过滤） |
| `GET /gmail/v1/users/me/messages/{id}` | 获取邮件元数据（headers、threadId、labelIds） |
| `GET /gmail/v1/users/me/messages/{id}?format=full` | 获取邮件正文（包含 body.data） |
| `GET /gmail/v1/users/me/history` | 增量变更（startHistoryId） |

### 2.3 Data Mapping

每封邮件提取为一条 Emerald 记忆：

| 邮件字段 | Emerald 映射 |
|---|---|
| `messageId` | `document_id`（去重依据） |
| `threadId` | `metadata.thread_id` |
| `From` / `To` / `Cc` | `metadata.participants` |
| `Subject` | `metadata.subject` |
| `Date`（邮件头） | `valid_from` |
| Body（提取为纯文本） | `content` |
| `labelIds` | `metadata.labels` |

### 2.4 Body Extraction

邮件的 `payload` 可能是：
- `text/plain` → 直接使用
- `text/html` → 用 Python 标准库 `html.parser` 提取文本（去除标签、保留段落结构）
- `multipart/alternative` → 优先取 `text/plain`，否则取 `text/html` 再提取
- `multipart/mixed`（含附件）→ 提取 `text/plain` 或 `text/html` 部分，附件跳过（v0.3.0 不处理）

提取后的纯文本交给 Emerald TextChunker 分块。

### 2.5 Sync Strategy

```
sync(mode=FULL):
  pageToken 分页遍历 messages.list(q="newer_than:30d")
  → 每个 message 检查 document_id 是否已存在
  → 不存在则 fetch body → 提交 pipeline

sync(mode=INCREMENTAL):
  从 connector 元数据读取 lastHistoryId
  → history.list(startHistoryId=lastHistoryId)
  → 筛选 messageAdded 事件
  → 只同步新增邮件
```

去重：用 `document_id = f"gmail:{messageId}"` 查询是否已摄入。

### 2.6 Webhook（延后到 v0.3.1）

Gmail push notification 需要：
1. 创建 GCP Pub/Sub topic + subscription
2. `users.watch()` 注册（每 7 天续期）
3. Pub/Sub push → Emerald webhook 端点

v0.3.0 不实现。定时同步（Celery Beat 每 4 小时）作为替代。

### 2.7 Config 新增

```python
# emerald/config.py — 已有 google_client_id / google_client_secret（复用）
# 无需新增 Gmail 专用配置
```

### 2.8 文件清单

| 文件 | 操作 | 说明 |
|---|---|---|
| `emerald/connectors/gmail.py` | 重写 | 完整实现替换 stub |
| `emerald/connectors/registry.py` | 修改 | 注册 `gmail` |
| `emerald/api/routes/connectors.py` | 无需修改 | 已有 `valid_providers` 含 `gmail` |
| `tests/connectors/test_gmail.py` | 新建 | Gmail connector 单元测试 |
| `tests/integration/test_gmail_e2e.py` | 新建 | E2E（需要真实 Google 凭证） |

## 3. Notion Connector

### 3.1 OAuth Flow

Notion OAuth 2.0（独立于 Google）：

```
授权端点: https://api.notion.com/v1/oauth/authorize
Token 端点: https://api.notion.com/v1/oauth/token
scope: 无需指定（Notion 集成在创建时确定权限）
```

OAuth 流程：
1. `get_auth_url()` → 构建 Notion OAuth 授权 URL（含 `client_id`、`redirect_uri`、`state`、`response_type=code`）
2. `handle_callback()` → `POST /v1/oauth/token` 交换 access_token
3. Notion token **不会过期**（Bearer token），无需 refresh。但仍存储 refresh_token 字段（nullable）。

### 3.2 API Endpoints

| Notion API | 用途 |
|---|---|
| `POST /v1/search` | 搜索可访问的页面和数据库 |
| `GET /v1/pages/{id}` | 获取页面属性 |
| `GET /v1/blocks/{id}/children` | 获取页面/block 的子内容（支持分页） |
| `POST /v1/databases/{id}/query` | 查询数据库行 |

### 3.3 Data Extraction

**页面文本提取（递归展开 blocks）：**

```
get_page_content(page_id):
  blocks = GET /v1/blocks/{page_id}/children (分页)
  text = ""
  for block in blocks:
    switch block.type:
      paragraph, heading_1/2/3, bulleted_list_item, numbered_list_item,
      toggle, quote, callout → 提取 rich_text 为纯文本
      child_page, child_database → 递归展开
      image, file, video, pdf → 跳过（v0.3.0）
      divider, table_of_contents → 跳过
  return text
```

**数据库行提取：**

```
get_database_rows(database_id):
  results = POST /v1/databases/{database_id}/query (分页)
  for each row:
    text = title_column_value + " | " + join(other_column_values)
```

### 3.4 Data Mapping

每个 Notion 页面映射为一条 Emerald 文档/记忆：

| Notion 字段 | Emerald 映射 |
|---|---|
| `page.id` | `document_id`（`notion:{page_id}`） |
| `page.last_edited_time` | `valid_from` / 去重依据 |
| `page.properties.title` | `metadata.title` |
| `page.url` | `metadata.url` |
| 展开后的 blocks 文本 | `content` |
| `page.parent.type` | `metadata.parent_type` |

### 3.5 Sync Strategy

```
sync(mode=FULL):
  POST /v1/search (filter=page, sort=last_edited_time desc, 分页)
  → 每个 page 检查 last_edited_time 是否变化
  → 变化则递归提取 → 提交 pipeline

sync(mode=INCREMENTAL):
  POST /v1/search (filter=page, sort=last_edited_time desc, 分页)
  → 只处理 last_edited_time > last_synced_at 的页面
  → 发现新变化即停止（已按时间降序排列）
```

Notion 不提供 history API，增量同步通过 `last_edited_time` 时间戳过滤实现。

### 3.6 Webhook

Notion webhooks 仍处于 public beta（2025 年发布），不稳定。v0.3.0 使用定时同步（Celery Beat 每 4 小时），`handle_webhook()` 返回 `NotImplementedError` 占位。

### 3.7 Config 新增

```python
# emerald/config.py
notion_client_id: str = ""
notion_client_secret: str = ""
```

| 文件 | 操作 | 说明 |

| `emerald/connectors/registry.py` | 修改 | 注册 `notion` |

## 4. 共享改进

### 4.1 Registry 注册

```python
# emerald/connectors/registry.py
from emerald.connectors.gmail import GmailConnector
from emerald.connectors.notion import NotionConnector
from emerald.connectors.github import GitHubConnector
from emerald.connectors.google_drive import GoogleDriveConnector

registry.register("gmail", GmailConnector)
registry.register("notion", NotionConnector)
registry.register("github", GitHubConnector)
registry.register("google_drive", GoogleDriveConnector)
```

### 4.2 测试策略

| 类型 | Gmail | Notion |
|---|---|---|
| **单元测试** | Mock httpx 响应测试 OAuth、body 提取、去重逻辑 | Mock httpx 响应测试 OAuth、block 递归、数据库行提取 |
| **集成测试** | 需要真实 Google 凭证 + 测试邮箱（CI 跳过） | 需要真实 Notion token + 测试页面（CI 跳过） |
| **边界测试** | 空邮件、HTML only 邮件、超大正文（>1MB）、未授权 token | 空页面、深层嵌套 block（>100 层）、超大数据库、已撤销 token |

### 4.3 验收标准

- [ ] `POST /v1/connectors/gmail/connect` 返回有效 Google OAuth URL
- [ ] `POST /v1/connectors/notion/connect` 返回有效 Notion OAuth URL
- [ ] OAuth callback 成功后凭据加密存储到 `connectors` 表
- [ ] Gmail 全量同步摄入最近 30 天邮件 → 可通过 `search()` 查到邮件内容
- [ ] Gmail 增量同步只处理新邮件（`historyId` 递增）
- [ ] Notion 同步递归提取页面 blocks → 可通过 `search()` 查到页面内容
- [ ] Notion 同步提取数据库行文本
- [ ] 重复同步不产生重复记忆（`document_id` 去重）
- [ ] 未连接时调用 `sync()` 返回错误（不崩溃）
- [ ] `DELETE /v1/connectors/gmail` 或 `notion` 可撤销 OAuth 凭证
- [ ] 所有单元测试通过，无需外部依赖

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Gmail API 配额限制（每秒 250 单位） | 同步时加 `asyncio.sleep(0.2)` 限流 |
| Notion API 速率限制（每秒 3 请求） | 请求间加延迟 + 429 重试 |
| 大邮箱同步超时 | 限制全量同步为最近 30 天；增量同步默认 |
| Notion block 递归过深 | 设置最大递归深度 = 10 层 |
| Google OAuth token 过期 | 使用 refresh_token 自动刷新 |
| Notion token 被用户撤销 | `status()` 检测并标记为 `error` |

---

## 6. 不在范围内（v0.3.1+）

- Gmail Pub/Sub webhook 实时推送
- Notion webhook 实时监听
- Gmail 附件提取（PDF、图片）
- Notion 图片和文件 block 提取
- Gmail 邮件线程上下文（同一 thread 的邮件关联）
- Notion 数据库的 filter/sort 视图处理
- 同步状态仪表板 UI
